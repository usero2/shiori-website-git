# AndroidでKomgaをShioriに接続する方法（表紙・読書進捗の同期対応）

自宅で **Komga** を運用していれば、ライブラリ全体がすでに自分のサーバー上に構築されているはずです。しかし、スマートフォンで読むとなると、ブラウザのタブを開くか、表紙も表示されない単純なファイル名のリストを表示するアプリを使うことになりがちです。

ShioriはKomgaに直接接続できます。正しく設定すれば、表紙、著者名、シリーズ構造、そして読書の進捗状況までサーバーと同期できます。この記事では、具体的な手順と、Shioriで提供されている3つのKomgaオプションのうちどれを選ぶべきかについて詳しく解説します。

## Komga、OPDS、それとも Komga API？ まずは正しい接続方法を選ぼう

サーバーを追加する際、Shioriはいくつかの自動入力オプション（クイックフィル）を提供しており、そのうち3つにKomgaの名前が含まれています。これらは機能が異なります：

* **Komga** — **OPDS v1** 経由で接続します。閲覧とダウンロードのみに対応しています。
* **Komga v2** — **OPDS v2** 経由で接続します。こちらも閲覧とダウンロードのみに対応しています。
* **Komga API** — Komgaの**ネイティブ REST API** 経由で接続します。**表紙、詳細な本情報、読書進捗の同期**に対応しているのはこれです。

OPDSは汎用的なカタログ規格であるため、Calibre、Calibre-Web、Standard Ebooks、Project Gutenbergなど、ほぼすべてのサーバーで動作します。しかし、その汎用性の高さゆえに限界もあり、ファイルをリスト表示してダウンロードするための最小限の情報しか保持できません。

一方、Komga独自のAPIはシリーズ、メタデータ、読書進捗を識別できるため、Shioriはファイル一覧ではなく本物のライブラリを表示でき、どこまで読んだかをKomgaに伝えることができます。

**特別な理由がない限り、「Komga API」を使用してください。**

## 必要なもの

* ネットワーク上で稼働しており、アクセス可能なKomgaサーバー
* Komgaの**ユーザー名とパスワード**（またはAPIキー）
* サーバーの**LANアドレス**（`localhost` ではないもの）
* Androidデバイスにインストールされた Shiori

> **なぜ `localhost` ではダメなのか？** `localhost` は「このデバイス自身」を意味します。スマホでこれを入力すると、サーバーではなくスマホ自身を指してしまいます。ネットワーク上でのサーバーのアドレス（例: `192.168.1.33`）を入力する必要があります。

## ステップ1 — Library Server リストを開く

Shioriで、下部ナビゲーションバーの **Collections**（コレクション）をタップします。**Library Server**（ライブラリサーバー）セクションまでスクロールし、その右側にある **+** ボタンをタップします。

![ShioriのCollectionsタブ。Library Serverセクションと追加ボタンが表示されている](01-collections-library-server.jpg)

ここはOPDSカタログ、Kavita、S3バケット、WebDAVシェアなど、あらゆるオンラインライブラリを追加する場所です。一度追加すれば、Komgaも他の情報源と並んで表示されます。

## ステップ2 — Add Library Server 画面の確認

**Add Library Server** 画面には、名前フィールド、カタログURL、自動入力チップの行、およびオプションのサインイン項目があります。

![Add Library Server画面。自動入力チップとサポートされているサーバーのヘルプテキストが表示されている](02-add-library-server-form.jpg)

下にスクロールすると、Shioriがサポートする各サーバータイプと期待される正確なURL形式が記載されています。一度目を通しておくと良いでしょう。この記事もその情報に基づいています。

## ステップ3 — サーバーアドレスを入力し、「Komga API」をタップする

ここでは手順の順序が重要です。チップの上のヒントには *"type the host, then tap your server"*（ホストを入力してからサーバーをタップ）と書かれています：

1. **Catalog URL** フィールドにサーバーのアドレスだけを入力します（例: `192.168.1.33`）
2. 次に **Komga API** チップをタップします

Shioriが入力内容を補完し、Komgaが必要とする完全なURL形式に変換します：

```
http://192.168.1.33:25600/api/v1
```

`25600` はKomgaのデフォルトポートです。変更している場合はポート番号を修正してください。下のスクリーンショットでは、本ガイド用に非デフォルトポートで実行しているため `25601` となっています。

次に **Sign-in** 項目にKomgaのユーザー名とパスワードを入力します。（または、ユーザー名を空欄にして、2番目のフィールドにKomgaのAPIキーを貼り付けることもできます。Shioriはどちらにも対応しています。）

![Komga API URLとサインイン情報が入力されたフォーム](03-komga-api-url-and-signin.jpg)

上部で分かりやすいサーバー名を設定し、お好みでアイコンを選択します。

## ステップ4 — 保存前に接続をテストする

**Test connection**（接続テスト）をタップします。このステップはスキップしないことをお勧めします。保存する*前*に、アドレス、ポート、認証情報がすべて正しいかどうかを確認できます。

![接続テスト結果: Connected — Komga (REST API)](04-test-connection-connected.jpg)

以下のように表示されれば成功です：

```
Connected — Komga (REST API)
```

このメッセージは2つのことを示しています。Shioriがサーバーに到達できたこと、そして単純なカタログにフォールバックすることなく**ネイティブ REST API** を検出できたことです。これ以外のメッセージが表示される場合、表紙や進捗の同期は行われません。

テストが失敗した場合は、順番に以下を確認してください：

* **Timed out / cannot reach** — IPアドレスが間違っているか、スマホがサーバーとは異なるネットワークに接続されています。両方が同じ Wi-Fi に接続されているか確認してください。
* **Unauthorized** — ユーザー名またはパスワードが間違っています。Komgaのユーザー名は通常、フルメールアドレスです。
* **Connected, but not as REST API** — URLの `/api/v1` 部分が抜けているか、ポート番号が間違っています。

確認できたら、右上隅の **Save**（保存）をタップします。

## ステップ5 — リストにサーバーが表示される

Komgaが **Library Server** リストに追加され、認証情報が保存されていることを示す南京錠のアイコンが表示されます。

![Library Serverリストに保存されたKomgaサーバー。URLはマスクされている](05-komga-in-library-server-list.jpg)

Shioriがこのリストでサーバーアドレスをマスクしていることに注目してください。これは意図的な設計であり、人にスマホを渡したりスクリーンショットを共有したりした際に、内部ネットワークの構成が画面に出ないように保護しています。

## ステップ6 — ライブラリを閲覧する

サーバーをタップして開きます。Komgaのライブラリ、カタログ自体を検索する検索ボックス、および並び替え機能が表示されます。

![Komgaカタログの閲覧。ライブラリとカタログ検索ボックスが表示されている](06-browse-komga-catalog.jpg)

上部に表示されるパンくずリスト（ブレッドクラム）で現在地を確認でき、戻るボタンを何度も押すことなく1タップで数階層前に戻ることができます。

## ステップ7 — 表紙、著者情報、ワンタップでの読書

ライブラリを開くと、ネイティブAPIを使用するメリットがよく分かります：

![表紙、タイトル、著者名、フォーマット、ファイルサイズが表示された本の一覧](07-books-with-covers-and-authors.jpg)

すべての作品について、Komgaのメタデータから直接取得された**表紙画像**、**タイトル**、**著者名**、**フォーマット**、**ファイルサイズ**が表示されます。各行には2つのアクションがあります：

* **Read**（本アイコン）— 読書を開始する
* **Download**（クラウドアイコン）— オフラインで読むために端末にコピーを保存する

REST API経由で接続しているため、読書位置はKomgaへと送り返されます。スマホで章の途中で読むのをやめてもKomgaが記憶しているため、次に別の端末で開いたときも続きから開始できます。

## ヒント

* **ダウンロードした本はオフラインで読めます。** 飛行機に乗る前や電波の悪い通勤経路に入る前にクラウドアイコンをタップしておけば、本は通常の本棚に保存されます。
* **画面上だけでなく、サーバー全体を検索します。** 検索ボックスはKomgaを直接検索するため、ライブラリが大きくなり数スクロールで収まらなくなっても目的の作品を見つけられます。
* **外出先から読む場合は？** ここで紹介した手順ではLANアドレスを使用しているため、自宅のネットワーク内でのみ機能します。外出先からKomgaにアクセスするには、自宅ネットワークへのVPN接続か、HTTPSを使用したリバースプロキシが必要です。Komgaを直接インターネットに公開するよりも、これらを適切に設定することをお勧めします。
* **2つ目のサーバーを追加する手順も同じです。** Kavita、Calibre-Web、OPDSカタログ、WebDAV、S3はすべてこの画面を使用し、Shioriが自動的にタイプを検出します。

## 自分だけのサーバー、本棚、そしてスマートフォン

Komgaを使えば、所有するハードウェア上で本を完全に管理できます。ネイティブAPIを介してShioriに接続すれば、モバイル環境でもその利点を損なうことはありません。他社のクラウドにライブラリを預けることなく、表紙、メタデータ、読書進捗の同期を手に入れることができます。

ShioriをダウンロードしてKomgaサーバーに接続し、読書の続きを楽しみましょう。
